# JuliUs NNUE 開発進捗レポート

ウケジャレイヤー（Ukeja Layer）用 対戦CPU「NNUE評価関数」の世代別学習成果をまとめる。
盤サイズ 4×4、探索は反復深化 α-β（置換表・killer・forward pruning・リーフ評価キャッシュ）。
評価は全ベンチ共通で **同一時間予算 120ms/手・カラー入替（swap）** で測定。勝率の括弧内は 95% 信頼区間。

最終更新: 2026-07-06

**4周目で頭打ち → 5周目で打開**: gen014 を生成器にした gen015 は seed 1 / seed 2 の 2 回とも gen014 に有意に負け越した（35.7% / 31.0%）＝小型64/16/16の容量飽和。そこで **データ多様性を強化**（openingRandomPlies 6→12・epsilon 0.1→0.25）し、**モデル容量を 96/24/24 に拡大**した gen016 が gen014 に **64.8%（200局, CI[58.1–71.5]）** で勝ち越し、プラトーを突破した。なお 128/32/32（gen017）は 51% で互角＝過大で無駄。

**6周目・学習の seed 依存が大きい（重要）**: gen016 を生成器にした6周目は、同一データ・同一アーキ（96/24/24）で **学習の乱数 seed だけを変えた 2 本**を作った。初回ベンチ（各100局相当）では両者の対 gen016 勝率が **seed1=gen018 42.0%（負け越し）／ seed2=gen118 75.0%（大勝）** と **33ポイント**も振れた。同一データで seed 違いだけでこの分散＝6周目は「改善できるが良い seed を引く必要がある」段階に入った。

**gen118 の追試（確証）**: 大分散を踏まえ gen118 を追加検証した。

- **vs gen016 追加 100局（head-to-head, swap, 120ms）**: 62.0%（62/100）[52.5–74.9→52.5–71.5]。5シャードとも 55–70% と一貫して勝ち越し。初回100局（75%）と合算すると **68.5%（137/200）[62.1–74.9]** で、CI下限が50%を明確に上回る＝**gen118 は gen016 に有意に勝ち越し**。
- **vs heuristic 99局**: **81.8%（81/99）[74.2–89.4]**。gen016 の 77.6% を上回り、gen014(88%) に迫る。

⇒ **gen118 を新チャンピオンとして採用**。一方 gen018（seed1）は不採用。**教訓: 6周目以降は複数 seed で学習し、最良 seed をベンチで選抜する運用が必須**（単一 seed だと改善世代を取りこぼす／劣化世代を誤採用するリスク）。

**7周目・多seed探索でプラトーを再突破（gen720）**: gen118 を新チャンピオンにした後、データを増やして再学習した。データは gen008（144万レコード＝gen016自己対戦を含む既存累積）に gen118 の自己対戦（ε0.25/openingRandomPlies12・21.7万レコード）を足した **gen009（166万レコード）**。ここで **6周目の教訓「学習seed依存が大きい」を運用に組み込み、14本のseedを学習してベンチで選抜**した。

- **seed分散は極端**: gen009 上の各seedの対 gen118 勝率（40局スクリーニング）は **2.6%〜65%** と激しくばらついた（seed10=gen920で2.6%、seed8=gen720で65%）。単一seedなら確実に取りこぼす水準。
- **当たりseed（gen720, seed8）を確証**: vs gen118 は 100局58.9%＋40局65%＋追加100局56.5% ＝ **合算 131/226 = 58.0%（95%CI[51.6–64.4]）** で有意に勝ち越し。vs heuristic は **79.0%（100局）[71–87]**（gen118の81.8%と同程度）。⇒ **gen720 を7周目チャンピオンに採用**。
- **失敗した実験（正直な記録）**:
  1. **gen008（データ増だけ）3seed**: 対 gen118 で 19〜49%。データ量+15%程度では単独で超えられず。
  2. **過剰多様化データ gen010（ε0.35/orp16, 202万レコード）5seed**: 対 gen118 で **10〜49%と全滅**。openingRandomPlies/epsilon を上げすぎると教師ラベル（探索スコア）が雑音化して逆効果。**多様性の甘い点は gen016 設定（ε0.25/orp12）付近**であり、それ以上の乱数はマイナス。

**運用結論**: プラトー領域では「良いデータ regime（ε0.25/orp12）× 多seed学習（10本以上）× ベンチ選抜」が改善の主エンジン。1周あたりの伸びは +数%（gen118→gen720 で対戦勝率58%）と小さいが、多seed選抜で着実に更新できる。

**8周目・gen122（さらに更新）**: gen720 を生成器に自己対戦（ε0.25/orp12）を足した **gen011（192万レコード）**で10seedを学習・選抜。対 gen720 のスクリーニング勝率は **3.3%〜86.7%**（seed分散は相変わらず極端）。当たりの **seed2=gen122** を確証すると vs gen720 **90.9%（100局）[85.2–96.6]**、vs heuristic **76.8%（99局）[68.4–85.1]**。⇒ **gen122 を8周目チャンピオンに採用**。

**注記（head-to-head と vs heuristic の乖離）**: gen122 は gen720 に 90.9% と圧倒するが、共通相手 heuristic への勝率は 76.8% で gen720(79.0%)・gen118(81.8%) とほぼ同水準。**エンジン同士の対戦は一貫したわずかな優位が勝率を大きく増幅する**ため、head-to-head の大差＝実力の大差ではない。vs heuristic が ~77–82% で頭打ち気味なのは、この容量（96/24/24）・この時間予算（120ms）での「真の強さ」が飽和に近いことを示唆する。世代ループは head-to-head では着実に更新できるが、**次の大きな一段（vs heuristic 85%超）にはデータの質・特徴量・容量など別レバーが要る可能性**。ただし人間・NNUE相手の実戦では最新世代（gen122）が最強。

**9周目・特徴量拡充で ~80% の壁を突破（gen415）**: 8周目まで vs heuristic が 77〜82% で頭打ちだった。時間予算スイープ診断（gen122 vs heuristic を同一予算で 120ms=80% / 300ms=80%）で、**頭打ちは探索深さ不足ではなく評価の質の限界**と判明。そこで **evaluate.js のヒューリスティック5項（トップ支配・埋めコマ・除去機会・機動力・物量の各 my−opp 差）をスカラー特徴として NNUE に追加**（SCALAR_DIM 4→9）。盤面 one-hot からは間接的にしか学べない構造知識を明示的に与える狙い。いずれも盤面全体の集計量で D4 対称不変・move生成不要（推論コスト増は無視できる）。

- **データ量交絡の切り分け**: 新特徴で新規生成した51万レコードでは全10seedが gen122 に 0〜17% と惨敗。だが**同一51万局面を4スカラーに truncate した対照群も vs heuristic 10〜53%と同程度に弱かった**＝真因は特徴ではなく**データ量不足**（gen122は累積192万で学習）と判明。
- **公平比較のための移行スクリプト**: `migrate_scalars.mjs` で gen011（192万・4スカラー）を **9スカラーへ厳密移行**（indices はスタック底→頂の順序と色を保持するため盤面を厳密再構成でき、extractFeatures 再実行→indices完全一致で全192万件検証OK）。gen122 と**同一局面**で特徴だけを変えた公平なデータセット gen011_9 を得た。
- **結果**: gen011_9 で10seed学習。対 gen122 スクリーニングは 13〜100% と分散大。当たりの **seed4=gen415** を確証すると **vs gen122 93.0%（100局）[88.0–98.0]**、**vs heuristic 88.8%（197局）[84.4–93.2]**。同条件の gen122 baseline は 80.0%（100局）[72.2–87.8]。⇒ **~80% の壁を突破し gen415 を9周目チャンピオンに採用**。
- **教訓**: (1) 頭打ちの主因は診断で切り分ける（探索深さ vs 評価質）。(2) 新レバー検証は**データ量を揃えて交絡を排除**する（移行で同一局面比較）。(3) 効いたのは特徴量拡充だが、恩恵は当たりseedのみ（中央値seedは非改善）＝**多seed探索は依然必須**。(4) 後方互換: 新スカラーは末尾追加なので旧モデル（scalarDim=4）は先頭4個のみ使用し無改変で動作。
- **追加seed探索（gen415超えの試み・不成立）**: gen011_9 で追加5seed学習。30局スクリーニングで gen1415 が対 gen415 74%と有望に見えたが、**74局で再検証すると 47.3%（互角）・vs heuristic 84.8%**＝小標本の分散に過ぎず gen415 を超えず。**採用前に必ず十分な局数で確証する**教訓を再確認（30局スクリーニングは当たり探索用、採用判断は100局規模で）。gen415 をチャンピオン維持。

**速度とのトレードオフ**: gen016 の eval は 3,148 ns（gen014 の 64/16/16 = 1,036 ns の約3倍）。同一時間予算では読むノードが減るが、それでも直接対決で勝つ＝1評価あたりの質が上回る。vs heuristic は 77.6% と gen014(88%) より低いが、これは高速な heuristic 相手ではノード数減の影響が出やすいため。人間・NNUE相手の実戦では gen016 が最強。データ生成ループは3倍遅くなる点に留意。

heuristic（従来の手作り評価関数）を 50% ラインとすると、gen003 の劣勢から一貫して上昇し、gen014 では約 88% まで到達した。

## 重要な技術的知見

1. **データ量が最大のレバー**: gen003→gen004 は同一アーキのままユニーク局面を約7倍にしただけで負け越し(31%)から教師超え(62%)に反転。当初の「詰みスコア飽和が主因」という仮説はデータ実測で否定され、真因は underfitting だった。

2. **小型ネットが速くて強い**: forward コストは隠れ層の幅（特に H2/H3 の密結合層）にほぼ比例。H1 半減はほぼ無効果、H2/H3 半減が効く。128/32/32 → 64/16/16 で eval を **2.0倍高速化**しつつ、128/32/32 がやや過学習気味だったため **棋力は逆に向上**（gen012 が gen005 に優勢）。

3. **世代ループが機能**: 現行最強モデルを生成器に自己対戦データを作り、既存データと結合累積して再学習 → 直前世代に有意に勝ち越すモデルが得られる、を反復。gen012→gen013→gen014 と着実に更新。

4. **推論の最適化**: リーフ評価を置換表にキャッシュ（棋力・決定性不変）。accumulator 差分更新は探索がイミュータブル局面を生成する構造上、効果が薄く不採用。

5. **データ生成ループの高速化**: 小型化＋キャッシュで NNUE 自己対戦のデータ生成は 15.3→6.7 秒/局（約2.3倍高速）。ベンチは 5シャード×20局を計10プロセス並列（10コア活用）で集計。

## 頭打ちの分析（4周目・gen015）

gen014 を生成器にした4周目は、独立した2回の学習（seed 1=gen015, seed 2=gen115）で
いずれも gen014 に負け越した。原因の推定:

- **自己対戦データの多様性低下**: 累積データが強いエンジン同士の似通った対局で埋まり、
  新規500局が新しい局面の学びをほとんど加えていない（探索は決定論的で、
  openingRandomPlies=6 / epsilon=0.1 の弱い乱数のみが多様性の源）。
- **モデル容量の飽和**: 64/16/16 は約127k局面・101万レコードに対して容量が小さく、
  これ以上の情報を吸収しきれていない可能性。

**打開策の候補（今後の実験）**:
1. **データ多様性の強化**: genData の openingRandomPlies と epsilon を上げ、探索深さ/時間も
   増やして局面と着手を多様化する。
2. **1周あたりの自己対戦局数の増量**（500→大幅増）、または古いデータの間引き/重み付け。
3. **モデル容量の見直し**: データが初期の18倍規模になったので、96/24/24 や 128/32/32 を
   gen006.jsonl で再学習して gen014 と比較（小型化の速度優位とのトレードオフを再評価）。
4. **ラベル品質の向上**: データ生成時の探索深さ/時間予算を上げて教師信号を高精度化。

## 再現手順（世代ループ 1 周）

```bash
# 1. 現行最強モデルを生成器に自己対戦データを5並列生成
for s in 1 2 3 4 5; do
  node tools/nnue/genData.mjs --games 100 --size 4 --depth 3 --timeMs 150 \
    --maxPlies 150 --seed <shardごとに変える> --augment 8 \
    --net models/gen<N>.json --out .../shard$s.jsonl &
done

# 2. pid をシャードごとにオフセットして既存の結合データとマージ（→ gen<M>.jsonl）
# 3. 学習（train.py 既定が 64/16/16 の高速アーキ）
python3 tools/nnue/train.py --data tools/nnue/data/gen<M>.jsonl --generation <N+1> --device auto

# 4. 採用判定（vs 直前世代・55%基準）とトラッキング（vs heuristic）を10並列で測定・集計
```

## 遊び方（人間 vs CPU）

`nnue-lab.html` をローカルサーバ経由で開き、CPU レベルで「NNUE」を選択 → モデル選択で世代を選ぶ（gen014 が最強、gen001 が最弱）。強さの違いを体感できる。
